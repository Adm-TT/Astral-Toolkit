# AT 1.1.1 的自动化代码，以及“注入 / 读内存”质疑的说明

> 写于 2026-11-01。对应源码：标签 [`v1.1.1`](https://github.com/Adm-TT/Astral-Toolkit/tree/v1.1.1)（提交 `b1b3d97`），也放在分支 [`release/1.1.1`](https://github.com/Adm-TT/Astral-Toolkit/tree/release/1.1.1)。下面每段代码都附了原文链接，可以点进去看上下文。

## 结论

- **1.1.1 及以前有模拟按键**，一共 4 处：防挂机、双击 W 自动跑、记录路标时自动输入 `/showlocation`、切到 AT 窗口时按一下 Alt。下面用红色标出原代码。**1.1.2 起全部删除**，当前版本 1.1.3 不模拟任何键盘或鼠标输入；1.1.1 及以前版本的读屏和上传功能已远程关闭。
- **AT 任何版本都没有读写游戏内存、没有注入、没有改游戏文件。** 有人看到的 `OpenProcess`、`SetWindowsHookExW`、`AttachThreadInput` 是什么、能做什么、不能做什么，见第二部分。
- 防挂机和自动跑是作者自己要加的功能，不是 AI 自作主张，判断错了，已经删掉。

## 二、被质疑“注入 / 读内存”的代码

### `OpenProcess(0x1000, …)`：只查进程名和权限

`0x1000` 是 `PROCESS_QUERY_LIMITED_INFORMATION`，Windows 里权限最低的一档进程句柄：只能查程序路径、是否还在运行、是否以管理员身份运行，**读不了也写不了内存**（读内存要 `PROCESS_VM_READ`，写要 `PROCESS_VM_WRITE`，AT 都没申请过）。用途：

- 判断最前面的窗口是不是 `StarCitizen.exe`：[`showloc.py` 第 182–196 行](https://github.com/Adm-TT/Astral-Toolkit/blob/b1b3d975b883923d13265f89fc119bf93f4d9d02/sc_mining/showloc.py#L182-L196)
- 判断游戏是不是管理员权限运行（是的话普通权限的 AT 收不到热键）：[`showloc.py` 第 261–285 行](https://github.com/Adm-TT/Astral-Toolkit/blob/b1b3d975b883923d13265f89fc119bf93f4d9d02/sc_mining/showloc.py#L261-L285)
- 看 AT 自己的辅助进程还在不在、统计 AT 自己的 CPU 和内存：[`helpers.py` 第 80–89 行](https://github.com/Adm-TT/Astral-Toolkit/blob/b1b3d975b883923d13265f89fc119bf93f4d9d02/sc_mining/helpers.py#L80-L89)、[`perfmon.py` 第 66–71 行](https://github.com/Adm-TT/Astral-Toolkit/blob/b1b3d975b883923d13265f89fc119bf93f4d9d02/sc_mining/perfmon.py#L66-L71)

```python
def _exe_path(hwnd):
    """窗口所属程序的完整路径（读不到返回空字符串）"""
    pid = wintypes.DWORD()
    _u32.GetWindowThreadProcessId(hwnd, ctypes.byref(pid))
    h = _k32.OpenProcess(0x1000, False, pid.value)          # PROCESS_QUERY_LIMITED_INFORMATION
    if not h:
        return ""
    try:
        buf = ctypes.create_unicode_buffer(520)
        size = wintypes.DWORD(520)
        if not _k32.QueryFullProcessImageNameW(h, 0, buf, ctypes.byref(size)):
            return ""
        return buf.value
    finally:
        _k32.CloseHandle(h)
```

### `SetWindowsHookExW(13, …)`：低级键盘钩子，不会进入游戏进程

`13` 是 `WH_KEYBOARD_LL`（低级键盘钩子）。这种钩子由 Windows 在 **AT 自己的进程里**回调，只能知道“哪个键被按下 / 松开”，不会把任何代码放进游戏进程（微软文档写明低级钩子不注入 DLL）。1.1.1 用它只看 W 和 S 两个键，给双击 W 自动跑用，**跟着自动跑一起在 1.1.2 删除**。[`helpers.py` 第 361–376 行](https://github.com/Adm-TT/Astral-Toolkit/blob/b1b3d975b883923d13265f89fc119bf93f4d9d02/sc_mining/helpers.py#L361-L376)

```python

    if run:
        def proc(n, wparam, lparam):
            try:
                if n == 0:
                    kb = ctypes.cast(lparam, ctypes.POINTER(KBDLLHOOKSTRUCT)).contents
                    if kb.vkCode in (VK_W, VK_S):
                        down = wparam in (0x0100, 0x0104)                 # WM_KEYDOWN / WM_SYSKEYDOWN
                        run.on_key(kb.vkCode, down, bool(kb.flags & 0x10))  # LLKHF_INJECTED
            except Exception as e:
                log(f"键盘监听出错：{e}")
            return u32.CallNextHookEx(None, n, wparam, lparam)
        cb = HOOKPROC(proc)
        hook = u32.SetWindowsHookExW(13, cb, k32.GetModuleHandleW(None), 0)    # WH_KEYBOARD_LL
        if not hook:
            log(f"双击W自动跑：键盘监听没装上（错误码 {ctypes.GetLastError()}）")
```

### `AttachThreadInput`：防挂机切窗口用

防挂机要把游戏窗口切到最前面，Windows 不让后台程序直接切，所以临时借用前台窗口的输入队列。这是窗口切换的常见写法，不读写别的进程的内存。**跟着防挂机一起在 1.1.2 删除**。[`helpers.py` 第 92–111 行](https://github.com/Adm-TT/Astral-Toolkit/blob/b1b3d975b883923d13265f89fc119bf93f4d9d02/sc_mining/helpers.py#L92-L111)

### 没有的东西

1.1.1（以及之后任何版本）的源码里都**没有**：`ReadProcessMemory`、`WriteProcessMemory`、`VirtualAllocEx`、`CreateRemoteThread`、往别的进程加载 DLL、`pymem` / `frida` 一类读写内存的库。

游戏文件只**读**两样：游戏自己写出的 `Game.log`（判断位置、是否坐上驾驶位），和玩家装的简中汉化 `global.ini`（对中文名）。AT 写的文件都在它自己的文件夹里。
