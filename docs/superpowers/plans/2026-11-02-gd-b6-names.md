# 游戏数据层 批 6（names / gamekey：名字与中英对照）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 中文物品名 → 英文名对照（`trade/names.table()` 及其派生）和物品游戏编号解析（`trade/gamekey.resolve`）的数据读取改走 `sc_mining/gamedata`，删掉它们直接读 JSON 和依赖 `shops.load / loot.load_index` 的代码，对外行为不变（含优先级、缺失回退、返回顺序）。

**Architecture:** 公开函数签名和返回形状不变：`names.table()` 仍返回 `{中文: 英文}` dict（同一版本内同一个对象），`to_english` 仍返回 `list[str]`、顺序不变，`gamekey.resolve` 仍返回 `(类名小写, uuid 或 '') | None`。新增 topic `gamedata/names.py`，只提供**原样有序行**（`zh_pairs / wiki_classes / alias_pairs / class_uuids`）；“首个胜出 / 后写覆盖”这类语义留在 `trade/names.py`、`trade/gamekey.py` 自己的内存建索引代码里，一行不改。缓存从 `lru_cache(maxsize=1)` / `_IDX` 改成 `VersionCache`，`table` 和 `_index` 保留 `cache_clear` 属性。`core/i18n.py` 不读 `data/`，不改；`itemsearch.wiki_items()` 还有批 4 和更新流程两个读者，不删。

**为什么新建 `gamedata/names.py` 而不是并进 `items.py`：** ① 这些是“原样名字对照”，不是物品目录行（矩阵 §6：`item_names` 与 `table()` 有 6 处不等价，别混在一个模块里让人误用）；② `items.py` 由批 1 定责（设计 §4.4），批 6 不改它就不会和批 3 / 批 4 撞；③ 设计 §2 本来就列了 `names.py`。

**Tech Stack:** Python 3.12 标准库；`tests/minipytest`。

**Spec:** 设计文档 v3（§2.2 缓存、§3.4、§4.3 批 6 一行）；矩阵 `docs/superpowers/specs/2026-11-02-gd-b6-callsites.md`；地基 API `sc_mining/gamedata/__init__.py`；批 1 定下的 `_ready.use(snap)` 用法和 `stockplaces.places` 的 `cache_clear` 保留写法。

## Review Focus

1. **`table()` 的优先级和顺序**（`zh_names` 胜过 `zh_only`、`_junk` 过滤、`zh_only` 要 ≥3 字、`zh_names` 缺失时整表空）：表里是导入时算好的结果，读出来的**有序**键值对必须和旧实现逐条相同——顺序错了，`_index` 首个胜出和 `suggest` 同分次序都会变。→ Task 2 测试 `test_table_equals_legacy_on_edge_sample`。
2. **两种冲突语义不能统一**：`to_english` 精确命中用 dict 推导（同规范化键**后写覆盖**），`_index` 用 `setdefault`（**首个胜出**）。迁移时任何“顺手合并成一份规范化 dict”都会让其中一边变。→ Task 2 测试 `test_to_english_exact_last_wins_index_first_wins`。
3. **不能从 `item_names` 组装**：物品目录会丢掉与商店 / 掉落撞键的汉化条目、丢掉英文折叠为空的条目、把英文换成首见拼写。`to_english` 必须返回汉化包里的原文拼写。→ Task 2 测试 `test_to_english_returns_source_spelling_not_item_en`。
4. **更新后立刻用新对照表，且 `cache_clear` 还能按名字调**：`localization._write_name_files` 直接调 `names.table.cache_clear()` / `names._index.cache_clear()`（外面 `try/except` 会吞掉 `AttributeError`，属性没了是静默失效）。→ Task 2 测试 `test_table_refreshes_after_rebuild_and_cache_clear_kept`。
5. **`gamekey` 的折叠和别名规则与物品目录不同**：`_fold` 不做 `l→i`；别名不过滤、后写覆盖；wiki 噪声物品（涂装）也要能解析；uuid 找不到按 `alt` 顺序兜底。→ Task 3 测试 `test_gamekey_resolve_equals_legacy_on_sample`。

- [ ] 红 → 实现：
  ```python
  _table_cache = VersionCache(identity=True)  # 键：zh_pairs() 返回的那份 tuple（topic 已按版本缓存，同版本同一对象）
  _index_cache = VersionCache(identity=True)  # 键：table() 返回的那份 dict

  def table():
      from .. import gamedata
      try:
          pairs = gamedata.names.zh_pairs()      # 不碰 _ready 等私有模块
      except gamedata.GamedataError:
          return {}                              # 不缓存：库好了下次立刻正常
      return _table_cache.get_for(pairs, lambda: {p.zh: p.en for p in pairs})
  setattr(table, "cache_clear", _table_cache.clear)
  ```
