## 0. 一句话

F8 先只 OCR 靠近屏高 24% 的标题带认物（中文→英文查库），不够再加高到 24%–70%、再全高；少送像素以提速，不换 OCR 模型、不做暗色板检测。

---

## 1. 背景与问题

现状 `_read_tooltip`（`astral_toolkit/trade/inspector.py`）按鼠标 X 选**全高**竖条（`get_hover_regions`，top=0、bottom=1），再 RapidOCR。说明框正文、制造商等一并进 det，像素多、偏慢。

观察（待样本复核）：说明框主体大致落在屏高 **24%–70%**；标题中文行贴近 **24%**。

认物并不需要读懂整段描述：本地汉化包 / 物品数据（`trade.names.canonical` 等）可在标题中英上收束。

---

## 2. 目标 / 非目标

**目标**

1. 减少送入 OCR 的像素，降低 F8 识别中位耗时（相对当前全高竖条主路径）。
2. 保持认物准确率不差于现状（样本回归）。
3. 宽度策略、驾驶位保护、品质/SCU/角标**行为保留**（角标等可继续用现有小裁）。

**非目标**

- 黑半透明板视觉检测  
- 换 PP-OCRv5 / v6 或其它 OCR 引擎  
- 本次优化品质 / SCU / 制造槽反推本身  
- 放开整屏兜底（驾驶位保护不变）

---

## 3. 裁切级联

命名常量（初值，可用样本调整；集中定义于 `inspector.py`）：

| 常量 | 初值 | 含义 |
|---|---|---|
| `TITLE_Y0` | `0.24` | 标题带顶（相对截图高） |
| `TITLE_Y1` | `0.36` | 标题带底 |
| `BODY_Y0` | `0.24` | 说明框带顶 |
| `BODY_Y1` | `0.70` | 说明框带底 |

**高度阶段（外层）**

1. **标题带**：`[TITLE_Y0, TITLE_Y1]`，OCR `urgent=True, native=True`  
2. **说明框带**：`[BODY_Y0, BODY_Y1]`，OCR 按现有主路径（非 native，除非实测证明标题带外也该 native）  
3. **全高**：`[0, 1]`，同现有竖条高度  

**宽度（每一高度阶段内）**  
仍调用 `get_hover_regions(cursor, width)`，顺序不变（对侧条带 → 30–70% 等）。

**停止条件**  
某次裁切 OCR 后，按 §4 得到**高把握库命中** → 立刻返回该 tokens / 名字 / 区域标签（标签需能区分阶段，便于日志，如 `30-50%@title`）。

补充（实现口径，2026-11-04）：标题带只认高把握库命中；**放大之后**（说明框带、全高档）另保留现有「英文名下紧跟体积 / 物品类型等锚点」的 `sure` 停止条件（§4「放大后若出现锚点，仍可与现逻辑组合」）。这样没进汉化包的物品停在原来的全高竖条这一档，不会每按一次 F8 都多跑一次整屏。

**驾驶位保护**  
与现逻辑一致：鼠标在中间带且全程未见说明框锚点、且无高把握库命中时，**不做整屏**；「全高」仅指当前宽度条带拉满高度，不是 `recognize(整图)`。

**F8 第一遍少认全高**（2026-11-07 PR #17 跟进）：`whole_screen=False`（F8 第一遍）时，标题带、说明框带里连说明框的样子（锚点 / 像样名字）都没见到就不认全高——说明框还没出来或根本没有，全高多半也认不出，直接回去让 F8 等一下再截；第二遍（`whole_screen=True`）、F6、窗口传图照旧认全高。第二遍不能也这样跳：名字在屏高 24%~70% 以外的少数界面（不是说明框，名字在屏幕最上面或最下面）只有全高认得出。

失败回退示意：

```
for y0,y1,stage,native in [(0.24,0.36,"title",True), (0.24,0.70,"body",False), (0,1,"full",False)]:
  for 各宽度:
    tokens = recognize(crop, urgent=True, native=native, offset=...)
    name = 抽标题 + 查库（§4）
    if 高把握命中: return
  # 无命中 → 下一高度
# 仍无：与现类似返回 best_candidate / last；中间带无锚点则跳过整屏
```

## 4. 标题抽取与查库顺序

同一次 OCR 的 tokens 内：

1. 取靠近标题带上方的**中文名**（沿用 `tooltip_pick` / `_anchor_name` 可用部分；中文折行最多拼 2 行；不拼锚点/属性行）。  
2. **先中文**走 `canonical`（及现有矿物精确路径）。  
3. 仅当中文**非高把握命中**时，用**第二行英文**再查。  
4. 中英都不够 → 本裁切失败，进入下一宽度或下一高度阶段。  
5. 仅有中文、无可用英文（矿石/食物等）且中文未命中 → 直接放大区域，不把正文杂行当第二行。

### 高把握 vs 弱命中

「停」必须是高把握，避免弱模糊中文唯一命中跳过英文：

| 算高把握 | 不算（继续英文或放大） |
|---|---|
| 英文 fold 精确命中汉化索引 | 仅中文 `canonical` 模糊档（当前 ratio≥0.75 那档）且无英文精确 |
| 中文规范化后精确命中 | 多个候选、不唯一 |
| 矿物精确 / 现有 `_mineral` 精确 | `canonical` 返回 `None` |
| （可选实现）英文模糊且 ratio≥0.9 且唯一 | `plausible_name` 有名但未入库 |

实现可抽小函数（如 `_strong_canonical(zh, en) -> (zh,en)|None`），内部复用 `names` 精确路径；弱模糊留给放大后再用完整 `canonical`，或仅在全高阶段放宽——**默认：弱模糊不在标题带阶段停**。

`sure`：窄带路径下以**高把握库命中**为准（不再强依赖「体积」锚点才 sure）；放大后若出现锚点，仍可与现逻辑组合。

黑名单（`_NOT_ITEM`、句子、锚点当名等）仍适用于抽行，避免聊天/HUD 进查库。

## 5. 品质 / SCU / 角标

- **保留** `tooltip_row` / `tooltip_quality` / `cell_labels` / 制造反推等现有逻辑。  
- **不为品质**再扫一整段说明框。  
- 标题带 tokens 里碰巧有品质行则用；否则依赖格子角标小 OCR（已有 `native=True`）及现有倒推；拿不到则与现在一样为空/`0` 规则不变。  
- **例外（制造品）**：标题带停下、且这件物品**有蓝图**（`for_item` 有结果）时，`inspect_item` 按同一宽度条带补认一次说明框带（24%~70%），只为了拿加成行给 `parse_mods` 倒推品质 / 各槽——制造品的加成行在说明框正文里（1440p 实测约屏高 59%~65%），标题带里没有；不补就违反 §7「制造品 `craft_override` 槽位品质行为不差于改前」。非制造品不补（仍满足「不为品质再扫一整段说明框」）。

## 10. F8 / F6 关系与后续优化

### 10.1 关系（为何本方案影响盘点）

| | F8 | F6 |
|---|---|---|
| 入口 | `hover_once` → `inspect_item(...)` | `_read_item` → `inspect_item(..., craft_override=True)` |
| 视觉核心 | 同一 `_read_tooltip` / 抽名 / `canonical` / 角标 | 同左 |
| 模式 | 按一次认一件 + 后台市价 | 会话内鼠标停住连认 + 库存对账 |
| 品质 | 读到的数字优先，缺了才倒推 | 制造品蓝图对上时倒推可压过读数 |
| 记账门槛 | 可显示「不确定」 | 必须 `sure`；失败同格最多试 3 次 |

因此：**改 `_read_tooltip` 级联 = F8 与 F6 共用加速**。盘点连点 N 格时总耗时近似按格数放大，比单次 F8 更吃像素。  
约束：F6 的 `sure` / `craft_override` / 角标语义本批不得故意削弱。

### 10.2 F6 专属优化建议（后续，非本 PR 必须）

按建议优先级：

1. **标题带级联（本方案）** — 每格 OCR 变便宜，盘点总时间受益最大。  
2. **按格子索引提前跳过 OCR** — 现有 `cells` 去重在识别**之后**；微抖会白跑全量 OCR。可先用现有格宽高估算（约 `0.065W × 0.11H`）判断「此格已点过」再决定是否 `inspect_item`。风险低，注意缩放。  
3. **失败重试更聪明** — 今失败仍 `0.3s × ≤3` 次 OCR；说明框未弹出时浪费大。可第 1 次 miss 后略延长等待，或无标题/无锚点时再重试。风险低。  
4. **会话内记住成功裁切阶段** — 同一背包页连续命中后，下一格先试上次成功的宽高阶段；滚动/换页需失效。风险中。  
5. **`craft_override` 懒计算** — 先名+角标；仅制造品缺品质或需槽位时再 `parse_mods` / `solve_slots`。风险中，须保持对账语义。  
6. **盘点首裁可比 F8 更矮（可选）** — 库存 UI 更稳时可单独常量；要盘点样本，勿与 F8 混用未验证的更狠裁切。

**暂缓 / 不建议**

- 再缩短 `STILL=0.35`（框未出易误检）  
- 为本优化换 PP-OCRv5/v6  
- 整页一次 OCR 认多格（与悬停说明框模型不符）  
- 让 F6 占用 F8 的 `busy`（现状不占 busy 是对的）；OCR 锁上 F8 `urgent` 插队保持

触及（仅后续 PR）：`app/engines/count.py`（去重时机、重试、会话裁切缓存）、可选 `tasks/count.py`；验证用连点盘点实机 + 既有 count 测试。
